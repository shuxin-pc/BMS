### S1 内部认证接口完全开放--可爆破密码、伪造审计、污染登录信息

| 字段 | 内容 |
|------|------|
| **编号** | S1 |
| **位置** | `src/Services/System/Bms.System.Api/Controllers/InternalAuthController.cs:13-16`<br>`src/Services/System/Bms.System.Api/Middleware/InternalServiceAuthMiddleware.cs:28-58`<br>`src/BuildingBlocks/Bms.BuildingBlocks.MultiTenant/Middleware/MultiTenantMiddleware.cs:42-52` |
| **分类** | 鉴权缺失 |
| **严重程度** | 严重 |
| **问题描述** | `InternalAuthController` 整个控制器标记 `[AllowAnonymous]`，`InternalServiceAuthMiddleware` 仅在请求带 `X-Internal-Service` header 时才触发校验（可选触发），不带该 header 时中间件完全透明。`MultiTenantMiddleware` 又把 `/api/internal/auth` 加入白名单直接放行。三者叠加导致外部攻击者无需任何认证即可直接调用 `/api/system/internal/auth/validate`（验证用户凭据）、`/audit-login`（伪造登录审计日志）、`/update-last-login`（任意修改用户登录信息）。 |
| **攻击场景** | 1. 攻击者直接 `POST /api/system/internal/auth/validate` 携带用户名字典进行密码爆破。<br>2. `POST /api/system/internal/auth/audit-login` 伪造任意用户的成功登录记录，污染审计溯源。<br>3. `POST /api/system/internal/auth/update-last-login` 任意修改用户的 LastLoginTime/LastLoginIp。 |
| **修复建议** | 1. 内部接口强制校验内部服务密钥（缺失 `X-Internal-Service` header 即拒绝，返回 401）。<br>2. 移除 `[AllowAnonymous]`，改为 `[Authorize]` + 自定义内部服务鉴权策略。<br>3. 密钥比较使用 `CryptographicOperations.FixedTimeEquals` 恒定时间比较。<br>4. 内部接口仅允许从网关或内网网段访问（网络层隔离）。 |

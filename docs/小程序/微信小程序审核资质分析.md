# 微信小程序审核资质分析

> 说明：针对店员端微信小程序（`docs/小程序/店员端微信小程序需求点清单.md`）上线审核所需资质的分析。
> 微信平台政策时效性强，本文基于既有知识整理，具体以提交审核时微信官方要求为准（待核实项见文末）。
> 分析日期：2026-09-09

## 结论

按当前 Store 服务实现的功能范围，**大概率不需要特殊行业资质，常规企业主体资质即可**。

## 判断依据

审核资质取决于小程序对外提供的服务内容。店员端小程序有三个关键定位，使其不属于「特殊资质行业」：

| 风险因素 | 当前现状 | 资质影响 |
|---------|---------|---------|
| 在线交易 | 不接微信支付，收银为记账模式（收款走线下） | 不触发电商/交易类目要求 |
| 面向消费者 | 使用者是内部店员，非 C 端顾客 | 不触发面向公众的服务类资质 |
| 预付卡/储值 | 储值/项目卡仅做记账与核销，不通过小程序售卡收款 | 单用途预付卡备案是线下业务合规问题，小程序层面一般不强制（待核实） |
| 医疗属性 | 美容档案/护理属于生活美容 | 若含医疗美容项目则需医疗机构执业许可——当前系统无此内容 |

## 常规准备材料

1. **企业主体认证**：营业执照 + 对公账户/法人验证 + 300 元/年认证费。
2. **管理员实名**：运营者身份证 + 手机号。
3. **类目选择建议**：选「IT 科技 → 基础服务/软件服务」或「商业服务 → 企业管理服务」方向（以创建小程序时类目向导实际可选为准，待核实）。

## 风险点与应对

1. **名称与简介措辞**
   - 避免出现「医美」「整形」「治疗」等医疗敏感词；「项目卡/治疗卡」在审核材料描述中建议表述为「护理卡/项目卡」。
   - 审核备注中主动说明：「门店内部员工管理工具，仅记录与核对门店经营数据，不含在线支付、不面向消费者提供售卡/充值服务」。

2. **审核员实际体验**
   - 审核员会打开小程序实际操作，可能看到顾客手机号、储值金额等数据并追问业务性质。
   - 应对：提审时提供带演示数据的门店，且演示账号下顾客姓名/手机号使用虚构数据。

## 待核实项

- 类目列表与各类目资质要求随微信政策调整，以 mp.weixin.qq.com 创建小程序时类目向导的实际要求为准。
- 预付卡备案在小程序审核层面的具体要求。
- 若租户门店业务实际涉及医疗美容，需单独评估资质。

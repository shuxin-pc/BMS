# 店员端微信小程序需求点清单

> 说明：本文档为店员端微信小程序需求清单，已经产品经理细化评审（2026-09-09），含导航结构、基础数据编辑边界与各评估项结论。不含技术架构方案。
> 交付分期：第一至十部分为第一期；第十一部分（AI 助手）为第二期，技师个人业绩与回访任务随二期交付。

## 一、产品定位与边界

- 面向门店店员的微信小程序，定位为"无 PC 门店的兜底营业终端"：部分门店没有 PC，店员通过小程序完成日常营业必需操作。
- 基础数据按"编辑边界分层"开放维护（见下）；技师档案、房间、设备、分类等低频数据由租户管理员或超级管理员在 PC 管理端维护。
- 适用任意角色（技师、前台、顾问、店长等），小程序暂不做权限过滤，各功能数据范围均为门店级全店可见；界面结构须预留权限过滤能力（见"三、导航结构"）。
- 收银为记账模式：顾客付款通过现金或店员线下收款完成，小程序仅负责录入支付方式与记账，不接入在线支付。
- 无需小票打印功能。
- 实施前提：小程序发布需要企业主体认证的 AppID 与微信类目审核（生活服务-美业类目），建议提前启动主体认证与资质准备。

### 基础数据编辑边界（分层开放）

- 小程序开放编辑（高频、低风险）：
  - 商品/服务：售价调整、上架/停售状态；
  - 顾客资料：姓名、手机号、标签等修正；
  - 项目卡配置、储值规则、积分/等级规则：全字段新增与编辑（覆盖租户管理员仅用手机管理的场景）。
- 小程序只读（回 PC 端维护）：商品/服务主档新增与分类、技师档案与技能、房间、设备、组织架构、角色权限、系统配置。
- 小程序侧的基础数据修改均记录操作人与时间（复用现有审计日志能力），配置类改错可追溯。

## 二、登录与门店

1. 登录方式双通道：账号密码登录 + 微信一键登录（流程参照既有小程序项目「保险销售 mini-app」的微信登录/绑定方案）。
2. 微信一键登录：wx.login 静默获取 code（全程无授权弹窗），后端以 code 换取 openid，匹配已绑定微信的员工账号后签发 token；未绑定时提示改用账号密码登录。
3. 微信绑定建立：首次使用先用账号密码登录，登录后在「我的」账号信息中自助绑定微信（提交 wx.login code，后端解 openid 写入当前账号）；同一微信号已被其他账号绑定时返回冲突提示。
4. 登录态：token 本地缓存，启动时已有 token 直接进入；请求 401 时清除登录态并引导重新登录；已绑定微信的账号重新登录时可走微信一键登录快速恢复。
5. 账号归属多个门店时，可切换门店；切换后所有页面数据按当前门店展示。
6. 实施确认项：BMS 后端为 OpenIddict 架构（现有 password/refresh_token 两种授权模式），微信登录与自助绑定接口需在 Identity/System 服务新增，User 表增加微信 openid 字段，具体落点待接口设计确认。

## 三、导航结构（信息架构）

1. 底部导航 4 个 tab：工作台、预约、收银、我的。
2. 登录/切店为登录流程，不占用 tab；"我的"页包含账号信息（个人信息、修改密码）与切换门店入口。
3. 顾客管理、项目卡核销、日结、商品与服务管理、基础数据管理为工作台功能宫格入口；收银与预约流程内可深链跳转顾客详情。
4. 消息中心为工作台顶部铃铛入口（含未读角标），不占 tab。
5. 权限过滤预留：宫格等聚合入口采用配置驱动渲染，入口项携带权限标识字段，当前一律显示；后续补充权限过滤时，无权限入口自动隐藏、流式布局自动重排，不产生空位或界面混乱。不设计"管理员专区"类硬分区。
6. AI 入口占位：工作台预留 AI 助手按钮，收银/预约页预留 AI 输入位，一期点击提示"即将上线"（详见第十一部分）。
7. UI 实现约束：禁止使用微信原生界面框架元素——底部导航不使用原生 tabBar，采用自定义 TabBar 组件实现（参照既有项目做法，配置驱动渲染，与权限预留机制一致）；页面导航栏统一自定义（navigationStyle: custom），自行处理状态栏高度、胶囊对齐与返回逻辑。微信系统级能力（登录 code 获取、授权弹窗、订阅消息请求等）不受此限。

## 四、工作台（Tab 1）

1. 今日概览：今日预约数、已到店数、今日营业额；营业额口径复用 PC 端工作台（含折算营收、退款冲减）。
2. 今日预约时间线清单：时间、顾客、项目、技师、房间、状态；支持快捷操作（到店确认）。
3. 顶部消息铃铛：未读角标，点击进入消息中心。
4. 功能宫格：
   - 顾客管理：查询、顾客详情、新建/编辑顾客；
   - 项目卡核销：独立核销入口（见第七部分）；
   - 日结：当日汇总与日结确认（见第九部分）；
   - 商品与服务管理：改价、上架/停售、库存只读查询；
   - 基础数据管理：项目卡配置、储值规则、积分/等级规则的新增与编辑（按编辑边界）；
   - AI 助手：占位入口。
5. 等级/积分规则展示：顾客详情页展示所属等级与积分规则，供店员向顾客解释。

## 五、预约管理（Tab 2）

1. 预约列表：按日期查看门店全部预约，展示顾客、项目、技师、房间、时段、状态。
2. 预约日历视图：按日/周查看预约分布。
3. 新建预约：选择顾客、服务项目、技师、日期时段；展示服务时长；支持查看技师当天可约时段。
4. 冲突校验：新建或改期时，系统自动校验所选技师、房间、设备在该时段是否已被占用，以及该顾客是否存在时段重叠的预约；冲突时阻止提交并提示原因。
5. 改期：对未开始的预约调整时间或技师。
6. 取消预约：填写取消原因或备注。
7. 到店确认：顾客到店后，将预约状态由"已预约"更新为"已到店"。
8. 服务完成：服务结束后将预约标记为"已完成"。
9. 预约状态机与 PC 端共用同一套（含爽约自动标记），小程序不单独定义状态。

## 六、顾客管理（工作台宫格）

1. 顾客查询：按手机号或姓名搜索顾客。
2. 顾客概览：展示基础信息、储值余额（区分实收与赠送）、积分、所属等级、标签；手机号等敏感字段默认脱敏展示（如 138****1234），点击查看明文（满足拨打联系需求），查看动作留痕。
3. 顾客消费记录：查看历史订单与消费明细。
4. 顾客卡包：查看名下储值卡与项目卡（名称、剩余次数、有效期、使用记录）。
5. 顾客档案查看，包括：
   - 美容档案（肤质、皮肤状况、护理偏好等）；
   - 身体数据记录；
   - 服务反应记录（含过敏与不适反应，需突出显示）；
   - 服务效果对比照。
6. 服务反应支持现场新增：服务过程中发现过敏或不适反应时，店员直接在小程序新增记录并标记（其余三类档案保持只读，新增/编辑回 PC 端）。
7. 新建顾客：到店新顾客建档，录入姓名、手机号（校验同门店内不重复）等基础信息。
8. 顾客资料编辑：支持修正姓名、手机号、标签等基础信息。

## 七、服务执行

1. 项目卡核销：选择顾客及其项目卡、本次服务项目，确认核销次数；核销提交前须回显卡名、项目与扣减次数并二次确认（防误触）；展示核销后剩余次数；核销记录可查。
2. 核销时可选技师、房间资源（与 PC 端一致，小屏交互可精简）。
3. 双入口：工作台宫格独立核销入口（纯服务核销，不产生订单）；收银结算时支持项目卡抵扣，两者共用同一核销逻辑。
4. 项目卡剩余次数不足或已过有效期时给出提示。

## 八、收银开单（Tab 3）

1. 快速开单：选择顾客（支持散客），添加商品或服务项目，录入数量与折扣，生成订单；选品时显示商品库存角标。
2. 支付方式记账：选择现金、储值、积分、项目卡抵扣、组合等支付方式完成收款记账；使用储值或积分支付时校验余额/积分是否充足并扣减。
3. 挂单：开单过程中可暂存订单；可查看挂单列表并恢复继续结算。
4. 项目卡销售：选择顾客与项目卡配置进行售卡，支持组合支付，售卡后按配置自动计算有效期。
5. 储值充值：选择顾客与充值档位（由储值规则预置），按规则自动计算赠送金额与积分；充值/售卡时展示等级/积分规则说明。
6. 退款：支持按订单退款（含部分退款），遵循现有退款规则（赠送余额不退、按比例扣回相关积分等），退款操作需二次确认；跨日退款/取消自动触发原下单日反日结重算（与 PC 端一致，不限当日）。
7. 折扣校验复用现有下单规则（折扣下限等），小程序不另设限制。
8. 防误触强确认：储值充值、项目卡售卡、退款三类敏感操作，提交前必须回显关键信息（充值档位与到账金额 / 卡配置与实付金额 / 退款单据与金额）并二次确认。

## 九、日结（工作台宫格）

1. 查看当日营业汇总：分支付方式的收入、开单数、充值、售卡等数据。
2. 日结确认：核对无误后执行日结确认操作；复用 PC 端同一日结数据与"汇总→确认→反日结"流程，双端互认状态。
3. 日结确认后不锁定开单，跨日变动通过反日结重算兜底（与 PC 端一致）。

## 十、消息中心（工作台铃铛）

1. 消息列表：站内消息集中查看，支持已读/未读标识。
2. 接收提醒类消息：每日预约提醒、顾客生日提醒、项目卡到期提醒。
3. 支持微信订阅消息授权引导，将关键提醒推送到微信服务通知（三类模板：预约提醒/生日提醒/项目卡到期提醒，授权引导时机待实施确认）。
4. 站内消息实时推送沿用现有 SignalR 通道（System 服务 MessageHub `/hub/messages`，按 `user_{userId}` 分组推送，同账号 PC 与小程序多端同时在线均可接收）；小程序端以 WebSocket 对接，断线自动重连，推送不可用时降级为进入页面刷新与下拉刷新。
5. 实施确认项：SignalR 客户端协议在小程序 WebSocket 上的适配方式、连接鉴权（token 传递）细节待接口设计确认。

## 十一、AI 助手（第二期）

### 统一交互模式

铁律：AI 只填表，写操作店员确认后提交。五个能力统一遵循"AI 解析 → 预填草稿 → 店员核对/修正 → 人提交"链路：

| 能力 | AI 产出 | 店员动作 |
|------|--------|---------|
| 一句话开单 | 订单草稿（顾客+项目/商品+数量） | 预填进开单表单，核对调整后提交 |
| 一句话预约 | 预约草稿（顾客+项目+技师+时间） | 预填进预约表单，经冲突校验后提交 |
| 回访话术生成 | 个性化文本（生日/久未到店/项目卡到期等场景） | 预览、复制 |
| 顾客档案摘要 | 只读汇总（突出过敏等安全提示） | 查看 |
| 自然语言查询 | 数据回答（文本/表格，如库存、本周储值金额） | 查看 |

- AI 的产物永远是标准表单的预填数据，不绕过表单直接创建。
- 解析模糊时（如同名顾客）在表单上留空项/选择项由店员手动补全，不报错中断。

### 入口形态（混合式）

- 功能内嵌：开单页、预约页顶部 AI 智能填单输入框（两个能力的终点即表单，路径最短）。
- 独立对话页：工作台入口进入，承载自然语言查询、回访话术、档案摘要等问答型能力。

### 一期预留（已在第一期落实）

1. AI 入口纯占位：工作台 AI 按钮 + 开单/预约页输入位，点击提示"即将上线"。
2. 开单、预约标准表单结构保持稳定，作为二期 AI 预填目标，二期不改主流程。
3. 结构化查询接口保持齐全（顾客搜索、项目搜索、技师可约时段、库存、营业汇总），二期 AI 为纯增量。
4. 一期不引入大模型依赖，不做 AI 相关后端开发。

### 二期待拍板项

- 语音输入（需录音授权与语音识别能力，可文字先行）。
- 大模型接入方式与供应商选型（架构层面决策）。

## 十二、范围外（由 PC 管理端维护）

- 商品/服务主档新增与分类管理（小程序仅支持改价与上下架）。
- 技师档案、技能、房间与设备资源。
- 库存采购、盘点、调拨管理（小程序仅支持库存只读查询）。
- 组织架构、角色权限、系统配置。

## 十三、评估结论（原"待产品经理评估项"）

1. 库存只读查询：纳入一期，挂工作台商品与服务管理入口，开单选品显示库存角标。
2. 顾客等级/积分规则展示：纳入一期，挂顾客详情页与收银充值/售卡场景。
3. 技师个人业绩查询（本月业绩、消耗统计）：随二期交付，依赖服务时间归集统计。
4. 回访任务列表与跟进记录：随二期交付，与 AI 回访话术能力配合。

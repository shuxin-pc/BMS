# 活动管理与样品赠品领用改造需求

> 创建日期: 2026-08-01
>
> 背景: 现有"赠品出库"独立入口与"样品领用"功能重叠，且实现粗糙（关联活动字段空悬、门店名称字段无效、前后端字段不一致、搜索条件后端不支持）。系统当前无活动管理功能，导致线下营销活动的赠品派发无法有效追踪归因。本次改造新增活动管理基础台账，删除赠品出库独立入口，扩展样品/赠品领用页面以覆盖无订单场景下的样品体验与赠品派发，订单内赠品仍由收银流程处理。

| 编号 | 需求 | 类型 | 说明 |

| R1 | 新增"活动管理"功能 | 新增 | 营销管理菜单下，基础台账，供其他业务关联 |

## 二、R1. 新增"活动管理"功能

### 2.1 业务定位

活动仅作**基础台账**处理，记录门店线下营销活动信息（名称、周期、备注），不与订单/库存直接绑定。提供被其他业务模块选择关联的能力，首个消费方为"样品/赠品领用"页面。

### 2.2 菜单

- 父菜单：营销管理（`store:marketing`，已存在）
- 新增菜单：

| 字段 | 值 |
|------|-----|
| Code | `store:marketing:activity` |
| Name | 活动管理 |
| Path | `/store/marketing/activity` |
| Component | `store/marketing/activity/index` |
| Icon | `Flag` |
| Sort | 2（在"宣传图片生成"之后） |
| Type | 1（菜单） |

同步新增按钮权限：`store:marketing:activity:view`（页面查看）。

### 2.3 活动实体（Activity）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| Id | long | - | 主键（雪花ID） |
| Name | string(100) | 是 | 活动名称 |
| StartTime | DateTime | 是 | 开始时间 |
| EndTime | DateTime | 是 | 结束时间（必须 > StartTime） |
| Remark | string?(500) | 否 | 备注 |
| IsDeleted | bool | - | 软删除标记（核心台账表，禁止物理删除） |
| TenantId / TenantCode / StoreId | - | - | 多租户隔离（继承 StoreBusinessEntityBase） |
| CreatedTime / UpdatedTime | - | - | 审计字段 |

**状态判断**：不设独立状态字段，通过时间动态计算：
- `now < StartTime` → 未开始
- `StartTime <= now <= EndTime` → 进行中
- `now > EndTime` → 已结束

**软删除理由**：活动被其他业务（样品/赠品领用）通过 ActivityId 关联，物理删除会导致历史领用记录的 ActivityId 悬空。软删除后，列表不展示已删除活动，但已关联的历史记录仍可通过详情接口查看活动信息。

### 2.4 接口设计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/store/activities` | 分页列表（支持名称模糊搜索、时间范围筛选） |
| GET | `/api/store/activities/{id}` | 详情 |
| POST | `/api/store/activities` | 创建 |
| PUT | `/api/store/activities/{id}` | 更新 |
| DELETE | `/api/store/activities/{id}` | 删除（软删除） |
| GET | `/api/store/activities/options` | 下拉选项（返回进行中活动，供其他业务选择） |

**`/options` 端点说明**：返回 `Id` + `Name` + `StartTime` + `EndTime`，过滤条件 `IsDeleted=false AND StartTime <= now <= EndTime`，按 StartTime 倒序。供样品/赠品领用页面的"关联活动"下拉使用。

### 2.5 前端页面

- **列表页**：
  - 搜索区：活动名称（模糊）、时间范围、状态（进行中/已结束/未开始，计算值）
  - 表格列：活动名称、开始时间、结束时间、状态（彩色标签）、备注、操作（编辑/删除）
  - 操作栏：新增活动
- **新增/编辑弹窗**：活动名称（必填）、开始时间（必填）、结束时间（必填，>开始时间）、备注
- **删除**：二次确认，软删除

### 2.6 数据库变更

- 新增表 `Activities`
- 新增迁移：`AddActivityTable`

## 五、R4. 订单内赠品出库解耦 SampleGiftOut + 关联活动

### 5.1 现状

`OrderAppService` 中订单内 Type=5 赠品出库流程：
1. `DeductSampleGiftOutAsync` 调用 `DeductItemBatchesAsync`（createSampleGiftOut=true）
2. 扣减批次库存 + 写 `InventoryLog(SourceType=GiftOutbound)`
3. **额外写 `SampleGiftOut` 记录**（二次记录，关联 OrderId）
4. 取消订单/全额退款时 `ReverseSampleGiftOutAsync` 删除这些记录

当前订单内赠品**不支持关联活动**。

### 5.2 改造目标

1. **解耦 SampleGiftOut**：删除二次记录，订单内赠品出库只保留批次扣减 + InventoryLog 流水
2. **支持关联活动**：订单内赠品项可选关联活动（非必填），活动归因写入 InventoryLog 流水

### 5.3 公共设计：InventoryLog 新增 ActivityId 字段

为统一活动归因数据源，`InventoryLog` 新增可空字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| ActivityId | long? | 关联活动ID（外键 Activities.Id，可空） |

**写入规则**：

| 流水类型 | SourceType | ActivityId 取值 |
|----------|-----------|-----------------|
| 样品/赠品领用出库 | SampleReceiveOutbound(9) | 从 SampleGiftReceive.ActivityId 取（R3） |
| 订单内赠品出库 | GiftOutbound(10) | 从订单项传入的 activityId 取（R4） |
| 其他流水（销售/调拨/盘点/采购退货等） | 其他 | null（不关联活动） |

**统一数据源意义**：活动维度报表（R5）只需查 `InventoryLog WHERE ActivityId IS NOT NULL`，无需 UNION SampleGiftReceives 和 OrderItems 两张表。

### 5.4 解耦 SampleGiftOut 修改点

| 文件 | 修改点 |
|------|--------|
| `OrderAppService.cs` | 移除 `createSampleGiftOut` 参数及所有 `_dbContext.SampleGiftOuts.Add(...)` 块 |
| `OrderAppService.cs` | `DeductSampleGiftOutAsync` 方法：保留方法名（语义仍为"赠品出库扣减"），但内部不再写 SampleGiftOut |
| `OrderAppService.cs` | `DeductItemBatchesAsync` / `DeductFromBatchesAsync`：移除 `createSampleGiftOut` 参数 |
| `OrderAppService.cs` | 删除 `ReverseSampleGiftOutAsync` 方法整体 |
| `OrderAppService.cs` | 删除两处调用点（取消订单、全额退款） |

库存扣减和流水追溯不丢失，退款时批次库存回滚由现有 `RefundRetailInventoryAsync` 处理，无需单独删 SampleGiftOut 记录。

### 5.5 订单内赠品关联活动修改点

| 文件 | 修改点 |
|------|--------|
| `OrderItemCreateDto.cs` | 新增 `ActivityId`（long?，仅赠品项有意义，非必填） |
| `OrderAppService.CreateAsync` | 识别赠品项的 activityId，传递给 `DeductSampleGiftOutAsync` |

| `OrderAppService.DeductItemBatchesAsync` / `DeductFromBatchesAsync` | 写 InventoryLog 时填充 ActivityId（仅赠品出库路径传值，销售出库传 null） |

## 六、R5. 报表数据源调整

### 6.1 活动维度报表（保留，数据源统一为 InventoryLog）

| 项 | 现状 | 改造后 |
|----|------|--------|
| 数据源 | `SampleGiftOuts` 按 `ActivityId` GroupBy | `InventoryLogs` 按 `ActivityId` GroupBy（WHERE ActivityId IS NOT NULL） |
| 方法 | `SampleGiftAppService.GetReportByActivityAsync` | 保留方法名，改查 InventoryLogs |
| DTO | `SampleActivityReportDto` | 保留，字段不变 |

**统一数据源**：依托 R4 引入的 `InventoryLog.ActivityId` 字段，活动维度报表一次查询覆盖两类场景：

```sql
SELECT ActivityId, ProductId, SUM(ABS(Quantity)) AS TotalQty
FROM InventoryLogs
WHERE ActivityId IS NOT NULL
  AND SourceType IN (SampleReceiveOutbound, GiftOutbound)  -- 9, 10
  AND Type = 2  -- 出库
GROUP BY ActivityId, ProductId
```

- **样品/赠品领用**（SampleReceiveOutbound=9）：从 SampleGiftReceiveAppService 写入的流水取
- **订单内赠品出库**（GiftOutbound=10）：从 OrderAppService 写入的流水取

关联 `Activities` 表填充活动名称、时间等显示字段。

### 6.2 样品维度报表（统计口径调整）

| 项 | 现状 | 改造后 |
|----|------|--------|
| 领用数量 | 查 SampleGiftReceives | 不变 |
| 出库数量 | 查 SampleGiftOuts | 改为查 InventoryLog（SourceType=SampleReceiveOutbound + GiftOutbound）按 ProductId 聚合 |

**统一口径**：删除 SampleGiftOuts 后，"出库数量"从 InventoryLog 统计，涵盖领用出库与订单内赠品出库两类。如需区分，报表可拆分为"领用数量"与"订单赠品数量"两列。

### 6.3 前端报表页面

- `src/views/store/sample/report/index.vue`：保留，数据接口不变（后端内部调整数据源）
- 如有"活动维度"切换 Tab，保留，接口不变

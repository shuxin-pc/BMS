# 前端动态路由改造规划方案

## 1. 背景与目标

### 1.1 问题现状

当前项目采用 **"静态路由 + 动态菜单"** 架构：

- **路由表**：全部静态写死在 `src/Admin/mes-admin/src/router/index.ts` 的 `routes` 数组中，每个业务页面都需要手动注册路由项。
- **菜单数据**：动态从后端 `getMenuTree()` API 获取，存入 `userStore.menus`，仅用于渲染侧边栏 `el-menu`。
- **两者解耦**：后端菜单数据（含 `component` 字段）未被前端用于路由注册，仅控制侧边栏显示。

**带来的问题**：

1. **双重维护**：新增页面需要同时修改前端代码（`router/index.ts`）和后端菜单配置，容易遗漏。
2. **部署耦合**：新增页面必须重新构建并部署前端，无法仅通过后端配置完成。
3. **不一致风险**：路由表与菜单数据可能不一致（路由有但菜单没有，或反之）。
4. **当前 `router/index.ts` 已注册约 50+ 个业务路由**，维护成本高。

### 1.2 改造目标

- 后端菜单成为路由的**唯一事实来源**。
- 后端菜单管理页面添加菜单项即可访问新页面，**无需修改前端代码**。
- 保留现有权限过滤机制（基于角色菜单授权 + 子系统隔离）。
- 保留现有侧边栏菜单渲染逻辑。
- 支持页面刷新、登录/登出、子系统切换等场景。

### 1.3 改造原则

- **最小破坏**：改造后所有现有页面访问行为不变。
- **渐进式**：可按子系统分批迁移，支持回滚。
- **安全优先**：组件路径必须做白名单校验，防止路径遍历攻击。
- **权限兜底**：不仅靠动态路由注册，路由守卫仍需校验权限。

**无 404 catch-all 路由**，访问未注册路径显示空白页。

### 2.2 菜单数据结构（后端返回，前端 `Menu` 类型）

```typescript
// src/Admin/mes-admin/src/api/system/types.ts
export interface Menu {
  id: number
  parentId?: number
  name: string
  path: string           // 如 "system/users"（相对路径）
  component?: string     // 如 "system/users/index"（相对 views 目录，不带 .vue）
  code?: string
  icon?: string

  isCache?: number

  isAlwaysShow?: boolean
  permissionCode?: string
  children?: Menu[]
```

**关键发现**：后端菜单数据已包含 `component` 字段，值规范为 `{模块}/{页面}/index`（相对 `src/views/` 目录，不带 `.vue` 后缀）。前端 `userStore.getMenus()` 已保留该字段（`stores/user.ts:505`），仅未用于路由注册。

### 2.3 后端种子数据 component 字段示例

| 菜单 | component 值 | 对应文件 |
|------|-------------|---------|
| 首页 | `dashboard/index` | `src/views/dashboard/index.vue` |
| 用户管理 | `system/users/index` | `src/views/system/users/index.vue` |
| 消息发送记录 | `system/messages/sent/index` | `src/views/system/messages/sent/index.vue` |
| 系统管理（一级目录） | `null` | 无（目录类型不对应页面） |

### 2.4 菜单加载与权限过滤流程（`stores/user.ts`）

1. `getMenus()` 调用 `getMenuTree()` API 获取完整菜单树。
2. `getSubsystemMenuIds()` 获取当前子系统的菜单 ID 列表。
3. `getRoleMenuIds()` 获取用户角色授权的菜单 ID 列表。
4. 取两者交集 = 最终授权菜单 ID 集合。
5. `filterMenusByPermission()` 过滤菜单树，只保留授权菜单及其祖先目录。
6. 结果存入 `this.menus`，供侧边栏渲染。

### 2.5 路由守卫现状（`router/index.ts:500`）

```typescript

  // 4. next()
})
```

**未做动态路由注册**，仅做权限数据加载。

## 3. 改造方案

### 3.1 总体架构

```
登录 → 获取用户信息 → 获取子系统 → 获取菜单树（含 component 字段）
                                    ↓
                              递归注册动态路由
                                    ↓
                              渲染侧边栏菜单
                                    ↓
                            路由守卫权限校验
```

### 3.2 静态路由保留范围

以下路由**保持静态注册**，不参与动态注册：

| 路由 | 原因 |
|------|------|
| `/login` | 登录页，无需权限 |
| `/`（layout 容器） | 所有业务页面的父容器 |
| `/dashboard` | 首页，登录后默认跳转，所有用户可见 |
| `/system/profile` | 个人中心，所有登录用户可见，不走菜单权限 |
| `/:pathMatch(.*)*` | 404 兜底（**新增**） |

### 3.3 动态路由注册逻辑

#### 3.3.1 组件收集（Vite `import.meta.glob`）

```typescript
// src/Admin/mes-admin/src/router/modules.ts
const modules = import.meta.glob('/src/views/**/*.vue')

/**
 * 根据后端 component 字段解析组件
 * @param component 后端返回的 component 值，如 "system/users/index"
 * @returns 解析后的组件导入函数，未找到返回 null
 */
function resolveComponent(component?: string | null) {
  if (!component) return null
  const path = `/src/views/${component}.vue`
  return modules[path] || null
}
```

**安全说明**：`import.meta.glob` 在构建时静态分析，只匹配 `src/views/` 下的文件，后端返回任意其他路径无法加载，天然防止路径遍历攻击。

#### 3.3.2 递归注册路由

```typescript
/**
 * 递归遍历菜单树，注册动态路由
 * @param menus 菜单树
 * @param isRegistered 已注册路由 name 集合（防重复）
 */
function registerDynamicRoutes(
  menus: Menu[],
  isRegistered: Set<string>
) {
  for (const menu of menus) {
    // 按钮类型(type=2)不注册路由
    if (menu.type === 2) continue

    // 目录类型(type=0)无 component，递归处理子菜单
    if (menu.type === 0) {
      if (menu.children?.length) {
        registerDynamicRoutes(menu.children, isRegistered)
      }
      continue
    }

    // 菜单类型(type=1)：有 path 且有 component 才注册
    if (menu.type === 1 && menu.path && menu.component) {
      const routeName = `dynamic_${menu.id}`
      if (isRegistered.has(routeName)) continue

      const component = resolveComponent(menu.component)
      if (!component) {
        console.warn(`[Router] 菜单 "${menu.name}" 的 component "${menu.component}" 未找到对应文件`)
        continue
      }

      // path 规范化为绝对路径
      const fullPath = menu.path.startsWith('/') ? menu.path : `/${menu.path}`

      router.addRoute('Layout', {
        path: fullPath,
        name: routeName,
        component,
        meta: {
          title: menu.name,
          icon: menu.icon,
          menuId: menu.id,
          permissionCode: menu.permissionCode,
          isCache: menu.isCache === 1
        }
      })
      isRegistered.add(routeName)
    }

    // 递归子菜单（菜单类型也可能有子菜单）
    if (menu.children?.length) {
      registerDynamicRoutes(menu.children, isRegistered)
    }
  }
}
```

#### 3.3.3 404 兜底注册

```typescript
/**
 * 注册 404 兜底路由
 * 必须在所有动态路由注册完成后调用，否则会拦截动态路由
 */
function registerNotFoundRoute() {
  if (router.hasRoute('NotFound')) return
  router.addRoute({
    path: '/:pathMatch(.*)*',
    name: 'NotFound',
    component: () => import('@/views/error/404.vue'),
    meta: { title: '页面未找到' }
  })
}
```

**需要新建** `src/views/error/404.vue` 页面。

### 3.4 路由守卫改造

```typescript
// src/Admin/mes-admin/src/router/index.ts
let isDynamicRoutesRegistered = false

router.beforeEach(async (to, _from, next) => {
  document.title = `${to.meta.title || '首页'} - BMS后台管理系统`
  const token = localStorage.getItem('token')
  const userStore = useUserStore()

  // 登录页直接放行
  if (to.path === '/login') {
    next()
    return
  }

  // 无 token 跳转登录
  if (!token) {
    next('/login')
    return
  }

  // 刷新后用户信息丢失，重新加载
  if (!userStore.userInfo.id || !userStore.userInfo.roles.length) {
    try {
      await loadUserPermissionData(userStore)
    } catch (error) {
      localStorage.removeItem('token')
      next('/login')
      return
    }
  }

  // 动态路由未注册时，先注册再重定向（保证 to 能匹配到路由）
  if (!isDynamicRoutesRegistered) {
    await registerDynamicRoutes(userStore.menus, new Set())
    registerNotFoundRoute()
    isDynamicRoutesRegistered = true
    // replace: true 避免 history 栈中留下未匹配的记录
    next({ ...to, replace: true })
    return
  }

  next()
})

 * 加载用户权限数据（用户信息 + 子系统 + 菜单 + 门店）
 */

  const { getCurrentUser } = await import('@/api/system')
  const user = await getCurrentUser()
  // ... 设置 userInfo、加载子系统、菜单、门店
  // 与现有 router.beforeEach 逻辑一致
}
```

### 3.5 登出时清理动态路由

```typescript

  // 清除动态路由

  dynamicRoutes.forEach(r => router.removeRoute(r.name!))
  isDynamicRoutesRegistered = false

  this.userInfo = { /* ... */ }

  // ... 其他清理
```

### 3.6 子系统切换处理

当前 `switchSubsystem()` 会重新调用 `getMenus()` 更新菜单数据。改造后需要：

1. 清除当前子系统的动态路由
2. 用新菜单数据重新注册动态路由

```typescript
// stores/user.ts 的 switchSubsystem() 中
async switchSubsystem(subsystemId: number | string) {
  const id = String(subsystemId)
  this.currentSubsystemId = id
  localStorage.setItem('currentSubsystemId', id)
  await this.getMenus()

  // 清除旧动态路由
  const dynamicRoutes = router.getRoutes().filter(r => r.name?.startsWith('dynamic_'))
  dynamicRoutes.forEach(r => router.removeRoute(r.name!))

  // 注册新动态路由
  registerDynamicRoutes(this.menus, new Set())
  registerNotFoundRoute()

  // 跳转到新子系统首页
  // ...
}
```

**注意**：`isDynamicRoutesRegistered` 标记需要从 `router/index.ts` 模块作用域移出，改为可被外部重置。可通过导出一个 `resetRouteRegistration()` 函数实现。

## 5. 关键设计决策

### 5.1 路由 name 命名规范

动态路由 name 使用 `dynamic_{menuId}` 格式：
- 保证唯一性（menuId 是 snowflake ID）
- 便于登出/切换子系统时通过前缀过滤清除
- 便于 `keep-alive` 的 `include` 列表管理

### 5.2 路由 path 规范化

后端菜单 `path` 可能是相对路径（如 `system/users`）或绝对路径（如 `/system/users`）。注册时统一转为以 `/` 开头的绝对路径，与现有静态路由保持一致。

### 5.3 不使用嵌套路由

虽然菜单树是多级的，但 Vue Router 中所有业务页面都作为 layout 的**平级子路由**注册，不使用嵌套 `<router-view>`。菜单的父子关系仅用于侧边栏显示。

### 5.4 动态路由注册时机

选择在 `beforeEach` 守卫中注册（而非登录成功后立即注册）：
- **优点**：覆盖刷新页面场景（刷新后 Pinia 状态丢失，守卫会重新加载菜单并注册路由）
- **缺点**：首次进入有轻微延迟（需等菜单加载完成）
- 用 `isDynamicRoutesRegistered` 标记避免重复注册

### 5.5 404 路由注册时机

404 catch-all 必须在**所有动态路由注册完成后**才能注册，否则会拦截动态路由。每次重新注册动态路由时，需要先移除 404 路由，注册完动态路由后再添加 404。

## 6. 风险与回滚

### 6.1 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 动态路由注册失败导致所有页面无法访问 | 高 | 保留旧静态路由代码（注释），出问题时快速回滚 |
| 菜单 component 字段与实际文件不一致 | 中 | 改造前做数据一致性预检（阶段 1.1） |
| 刷新页面白屏（路由未及时注册） | 中 | 守卫中 `next({ ...to, replace: true })` 确保路由注册后再放行 |
| 子系统切换时路由残留 | 中 | 切换时先清除所有 `dynamic_` 前缀路由 |
| `import.meta.glob` 未匹配到组件 | 低 | 控制台警告 + 跳过注册，不影响其他页面 |

### 6.2 回滚方案

1. 保留改造前的 `router/index.ts` 完整副本（注释或 git 分支）。
2. 出现严重问题时，通过 git revert 回滚 `router/index.ts`、`stores/user.ts`、`layout/index.ts` 三个文件。
3. 新建的 `router/modules.ts`、`views/error/404.vue` 不会被引用，可保留不影响系统。

### 6.3 渐进式改造（可选）

如担心一次性改造风险，可采用渐进式方案：
1. 先实现动态路由注册逻辑，但**保留所有静态路由**（动态注册与静态注册并存，Vue Router 后注册的同名路由会覆盖前者）。
2. 验证动态路由工作正常后，逐个删除静态路由项。
3. 最终清理完毕，移除所有业务静态路由。

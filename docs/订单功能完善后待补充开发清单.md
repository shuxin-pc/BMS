### 当前实现

关联订单为**选填**（早期的"对比照片必须关联服务订单"强制校验已移除）：

- `ServiceComparisonPhotoValidators.cs:11-14` / `ServiceReactionValidators.cs:11-14`：`OrderId`、`ProductId` 均为可空，仅校验有值时必须 > 0
- `ServiceComparisonPhotoAppService.cs:126-134` / `ServiceReactionAppService.cs:143-149`：`OrderId` 有值时校验订单存在且属于当前租户 + 门店
- `ServiceComparisonPhotoAppService.cs:137-142` / `ServiceReactionAppService.cs:153-160`：`ProductId` 有值时校验必须是 `ProductMaster.Type == 2`（服务类商品），并以主档名称覆盖 `ServiceItem`，固化为当时的名称快照
- 前端两个 tab 的"关联订单"下拉均为选填，客户上下文由服务档案页顶部统一提供；按 `customerId` 拉取订单后**前端过滤** `orderType === 2 || 3`（服务 / 疗程卡核销）
- 前端"服务项目"已从自由文本输入改为下拉选择（仅服务类上架商品，`type=2 & status=1`）

### 待验证项

订单功能完善、能产生真实的服务订单与疗程卡核销订单后，**照片管理与反应记录两个 tab 都需要**实际验证：

1. **下拉能否取到订单**：切换顶部客户后，"关联订单"下拉能正确列出该客户的服务订单和疗程卡核销订单，标签展示的订单号、类型、下单日期正确，且下拉**不是禁用状态**
2. **无订单客户的表现**：客户没有任何服务/核销订单时，下拉为空，是否给出明确提示（当前仅为空列表，无空态文案）
3. **服务项目与所选订单是否匹配**：选中订单后，"服务项目"下拉当前仍是全部服务类商品，**不会按该订单的明细收窄**。需验证实际使用中是否会出现"填写的服务项目与订单实际项目不一致"的脏数据，并据此决定是否实施下方开发项 4
4. **提交链路**：选中订单后提交成功，记录的 `OrderId` 正确落库；`ServiceItem` 落库为所选服务项目的主档名称
5. **跨门店隔离**：切换门店后，下拉不应出现其他门店的订单；提交其他门店订单 ID 应被后端拦截

### 待补充开发项

1. **订单选项拉取方式不合理**（`PhotoUploadDialog.vue:191`、`ReactionPanel.vue:332`）
   两处均用 `getOrders({ customerId, pageIndex: 1, pageSize: 9999 })` 拉全量再前端过滤类型。原因是 `OrderQuery.orderType` 只支持单值，无法一次查询"服务 + 疗程卡核销"两种类型。
   建议：后端提供按客户查询可关联订单的选项接口（限定 `OrderType in (2,3)`、`Status` 为有效状态），或 `OrderQuery` 支持 `orderType` 多值传入，前端改为分页/远程搜索，避免 `pageSize=9999`。两个 tab 应复用同一接口。

2. **后端未校验订单类型与订单归属客户**（`ServiceComparisonPhotoAppService.cs:126-134`、`ServiceReactionAppService.cs:143-149`）
   当前仅校验订单存在且同租户同门店，未校验：
   - 订单 `OrderType` 是否为 2（服务）/ 3（疗程卡核销）
   - 订单的 `CustomerId` 是否与记录的 `CustomerId` 一致

   前端过滤可被绕过，需在**两个服务**中补齐这两项校验。

3. **照片管理列表未展示关联订单号**
   `ServiceComparisonPhotoDto.OrderNo` 已由后端填充（`ServiceComparisonPhotoAppService.cs:77-86`），但照片配对卡片头部（`PhotoPanel.vue:48-53`）只展示服务项目与拍照日期，未展示订单号。
   建议：卡片头部展示关联订单号，便于追溯；同时考虑搜索条件增加"订单号"。
   注：反应记录 tab 已在表格列与详情弹窗中展示关联订单号（`ReactionPanel.vue:69-73`、`:200`），无需改动。

4. **服务项目未与订单联动**（两个 tab 均存在）
   "服务项目"已改为服务类商品下拉（后端会校验类型并固化名称快照），但**与所选订单无任何联动**：选中订单后下拉仍是全部服务类商品，可能出现填写内容与订单实际项目不一致。
   建议：选中订单后，将"服务项目"下拉收窄为该订单明细中的服务项目（或默认带出订单明细的服务项目、允许改为其他项）。这依赖订单明细查询接口按 `orderId` 返回服务类明细行。

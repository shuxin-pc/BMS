# 商品管理菜单拆分改动清单（方案B）

> 状态：待实施 | 日期：2026-08-29 | 决策：拆分为 2 个一级菜单
> 现状对照见：`docs/门店子系统菜单现状清单.md`

## 一、目标

将「商品管理」一级菜单下的 16 项按业务域拆为 **2 个一级菜单**，保持「一级菜单 → 二级页面」的两级结构。
**前端路由、页面文件、侧边栏渲染均不修改**（菜单 Path / Component 不变）。

## 三、改动项清单

### 1. `StoreMenuSeedData.cs`（核心改动）

- 新增一级目录：`store:purchase-inventory`（Sort = 4）。
- 上表 8 项：`ParentCode` 由 `store:product` 改为 `store:purchase-inventory`，`Code` 按表调整，`Sort` 重排 1~8。
- 商品管理保留 8 项：`Sort` 重排为 1~8。
- 一级菜单排序调整：最终一级菜单顺序见【第四节】（已手动调整为 15 个），实施时以该顺序为准调整各一级菜单 `Sort`（1~15）。

### 2. 按钮权限（Type=2）：无需改动

- `store:product:supplier:edit` / `create:public` / `edit:public`（供应商管理，保留在商品管理）
- `store:product:master:edit`（商品主档）
- `store:product:profile:edit`（商品档案）
- 上述按钮的 ParentCode 均指向保留菜单，不受影响。
- 「页面查看」按钮（`xxx:view`）按 Type=1 菜单自动生成，Code 随新菜单自动生成，无需手工处理。

### 3. 权限 / 授权数据（需处理）

- 菜单 Id 与 Code 变化 → 历史「角色-菜单」授权（RoleMenuAuths）失效，**需重新分配**。
- 测试环境若开启 SeedTestData：`Bms.System.Infrastructure/SeedData/TestSeedData/Menus.json` 与 `RoleMenuAuths.json` 中若含 Store 菜单，需同步更新（菜单 Id 以数据库为准，规则见 `StoreMenuSeedData.cs` 头部注释）。

### 4. 前端：无需改动

- 路由 `/store/product/*`、页面文件 `src/views/store/product/*`、侧边栏两级渲染均保持不变（菜单 Path / Component 未变，不存在 404 风险）。

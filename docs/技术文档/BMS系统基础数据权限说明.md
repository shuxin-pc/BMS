## 2. 核心实体与关系

### 2.1 实体一览

| 实体 | 说明 | 归属 |
|------|------|------|
| 租户 (Tenant) | 多租户架构下的租户单位 | 平台级 |
| 用户 (User) | 系统使用者，关联租户和角色 | 租户级 |
| 角色 (Role) | 权限集合，定义功能与数据访问范围 | 租户级 |
| 菜单 (Menu) | 功能入口，定义页面/按钮权限 | 平台级 |
| 子系统 (Subsystem) | 功能模块分组，关联菜单 | 平台级 |
| 组织 (Organization) | 企业组织架构，用于数据隔离 | 租户级 |

## 3. 角色体系

### 3.1 角色分类

MES系统采用两级角色体系：

| 角色类型 | 角色代码 | 角色名称 | 说明 |
|---------|---------|---------|------|
| 平台级 | `super_admin` | 超级管理员 | 属于平台租户，可管理所有租户、系统配置 |
| 租户级 | `tenant_admin` | 租户管理员 | 属于具体租户，可管理本租户内的用户、角色、业务数据 |
| 租户级 | 自定义角色 | 普通角色 | 租户管理员创建，用于业务功能权限控制 |

### 3.3 角色权限边界

| 权限项 | 超级管理员 | 租户管理员 | 普通角色 |
|-------|-----------|-----------|---------|
| 创建租户 | ✅ | ❌ | ❌ |
| 禁用/删除租户 | ✅ | ❌ | ❌ |
| 管理子系统 | ✅ | ❌ | ❌ |
| 分配子系统给租户 | ✅ | ❌ | ❌ |
| 创建租户用户 | ✅ (可指定租户) | ✅ (自动本租户) | ❌ |
| 创建租户角色 | ✅ | ✅ | ❌ |
| 分配角色菜单权限 | ✅ | ✅ | ❌ |
| 分配数据权限 | ✅ | ✅ | ❌ |
| 查看全部租户数据 | ✅ | ❌ | ❌ |

## 4. 用户体系

### 4.1 用户与租户的关系

- 每个用户必须归属于一个租户
- 超级管理员归属于"平台租户"(platform)
- 普通用户归属于具体的业务租户

### 4.2 用户与角色的关系

- 每个用户绑定一个角色（单选）
- 超级管理员 → `super_admin` 角色
- 租户管理员 → `tenant_admin` 角色
- 普通用户 → 自定义角色

### 4.3 用户创建规则

| 创建者 | 可选角色 | 租户归属 |
|--------|---------|---------|
| 超级管理员 | 所有角色 | 可指定任意租户 |
| 租户管理员 | 仅普通角色 | 自动当前租户 |
| 普通角色 | ❌ 无权限 | - |

## 5. 菜单体系

### 5.1 菜单类型

| 类型值 | 类型名称 | 说明 |
|--------|---------|------|
| 0 | 目录 | 菜单分组，可包含子菜单 |
| 1 | 菜单 | 页面入口，对应具体功能页面 |
| 2 | 按钮 | 页面内操作按钮，用于权限控制 |

### 5.2 菜单属性

| 属性 | 说明 |
|------|------|
| name | 菜单名称 |
| path | 路由路径 |
| component | 组件路径（菜单类型使用） |
| icon | 图标 |
| code | 权限标识（按钮类型使用） |
| isVisible | 是否显示 |
| isCache | 是否缓存 |
| sort | 排序号 |

### 5.3 菜单权限控制

- 菜单权限通过 RoleMenuAuth 表管理
- 用户登录后，根据角色获取可访问的菜单
- 前端根据菜单权限动态渲染页面

#### 5.3.1 菜单过滤逻辑

用户登录后，左侧菜单的显示需要经过以下步骤过滤：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         菜单过滤流程                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1. 获取当前子系统关联的菜单ID列表 (SubsystemMenu)                         │
│         │                                                                   │
│         ▼                                                                   │
│  2. 获取用户角色拥有的菜单权限ID列表 (RoleMenuAuth)                        │
│         │                                                                   │
│         ▼                                                                   │
│  3. 取两者交集 = 最终授权菜单ID列表                                         │
│         │                                                                   │
│         ▼                                                                   │
│  4. 遍历菜单树，筛选需要显示的菜单：                                        │
│     - 如果菜单ID在授权列表中 → 显示                                         │
│     - 同时递归显示该菜单的所有父级目录                                       │
│     - 首页(/dashboard)始终显示                                              │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**过滤规则说明：**

| 步骤 | 说明 |
|------|------|
| 子系统过滤 | 只显示当前子系统关联的菜单 |
| 角色权限过滤 | 只显示用户角色被授权的菜单 |
| 取交集 | 同时满足子系统关联和角色权限的菜单 |
| 祖先节点 | 显示授权菜单时，必须同时显示其所有父级目录 |

**示例：**

假设菜单结构如下：
```
├── 首页 (id=1, /dashboard)
├── 系统管理 (id=10, type=0)
│   ├── 用户管理 (id=101, type=1)
│   └── 角色管理 (id=102, type=1)
└── 生产管理 (id=20, type=0)
    ├── 生产订单 (id=201, type=1)
    └── 生产报工 (id=202, type=1)
```

用户角色只被授权 `用户管理(id=101)` 和 `生产订单(id=201)`：

- 首页(id=1) → 始终显示
- 用户管理(id=101) → 显示，同时显示父级"系统管理(id=10)"
- 生产订单(id=201) → 显示，同时显示父级"生产管理(id=20)"

最终显示结果：
```
├── 首页
├── 系统管理
│   └── 用户管理
└── 生产管理
    └── 生产订单
```

## 6. 子系统体系

### 6.1 子系统定义

子系统是功能模块的顶层分组，每个子系统包含一组相关的菜单。例如：

| 子系统名称 | 子系统编码 | 说明 |
|-----------|-----------|------|
| 系统管理 | system | 系统配置、用户、角色、菜单等 |
| 生产管理 | production | 生产计划、生产执行等 |
| 质量管理 | quality | 质量检验、质量分析等 |
| 设备管理 | equipment | 设备台账、保养维修等 |

### 6.2 子系统与菜单的关系

- 子系统与菜单是多对多关系 (SubsystemMenu)
- 一个子系统可包含多个菜单
- 一个菜单可属于多个子系统（支持跨子系统复用）

### 6.3 子系统管理

#### 6.3.1 子系统管理功能

| 功能 | 说明 |
|------|------|
| 新增子系统 | 创建子系统基本信息 |
| 编辑子系统 | 修改子系统名称、图标等 |
| 删除子系统 | 删除前检查是否已被租户使用 |
| 分配菜单 | 为子系统关联菜单 |
| 禁用/启用 | 控制子系统可用状态 |

#### 6.3.2 子系统状态

- **启用**：租户可分配使用
- **禁用**：租户不可分配，但已分配的仍保留

### 7.3 权限继承

当子系统分配给租户后，**租户管理员角色自动获得该子系统的所有菜单权限**。

这意味着：
- 租户管理员可以访问子系统下的所有功能
- 租户管理员可以为其他角色分配该子系统下的菜单权限

## 9. 数据权限

### 9.1 数据权限类型

数据权限控制角色对应的用户能访问哪些组织的数据：

| 类型值 | 名称 | 说明 |
|--------|------|------|
| 1 | 全部数据 | 查看角色所属租户内的所有数据 |
| 2 | 部门及以下 | 查看本部门及下属子部门的数据 |
| 3 | 仅本人 | 只能查看自己创建的数据 |
| 4 | 自定义 | 可指定具体的组织ID列表 |

### 9.2 特殊角色数据权限

| 角色 | 数据权限 |
|------|---------|
| 超级管理员 (super_admin) | 可查看所有租户数据（不过滤租户ID） |
| 租户管理员 (tenant_admin) | 默认全部数据权限 |

### 9.3 超级管理员不受数据权限限制

**重要规则**：超级管理员（isSuperAdmin=true）不受数据权限过滤限制，可以查看所有数据。

对于非超级管理员，系统会根据其角色的数据权限配置来过滤查询结果。

### 9.4 数据权限过滤逻辑

#### 9.4.1 权限获取流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         数据权限过滤流程                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1. 用户登录后，获取当前用户信息                                             │
│         │                                                                   │
│         ▼                                                                   │
│  2. 获取用户绑定的单个角色（每个用户只能绑定一个角色）                       │
│         │                                                                   │
│         ▼                                                                   │
│  3. 获取该角色的数据权限配置 (DataPermission)                               │
│         │                                                                   │
│         ▼                                                                   │
│  4. 根据权限类型计算可访问的组织ID列表                                       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 9.4.2 各权限类型的过滤规则

| 权限类型 | 过滤规则 |
|---------|---------|
| 全部数据 (1) | 无过滤，返回同租户下的所有数据 |
| 部门及以下 (2) | 返回用户所在部门 + 所有下属子部门的用户 |
| 仅本人 (3) | 只返回 userId 等于当前用户ID的记录 |
| 自定义 (4) | 只返回组织ID在自定义列表中的数据 |

#### 9.4.3 过滤实现示例

以用户管理为例，查询用户列表时的过滤逻辑：

```
1. 判断是否为超级管理员
   ├─ 是 → 不过滤，直接返回同租户所有用户
   └─ 否 → 继续下一步

2. 获取当前用户可访问的组织ID列表
   ├─ 全部数据 → 返回所有组织ID（同租户）
   ├─ 部门及以下 → 返回用户所在部门 + 下属子部门ID
   ├─ 仅本人 → 返回 [当前用户ID]（作为特殊标记）
   └─ 自定义 → 返回自定义配置的组织ID列表

3. 查询用户时按组织ID过滤
   ├─ 仅本人 → WHERE userId = 当前用户ID
   └─ 其他 → WHERE organizationId IN (可访问的组织ID列表)
```

### 9.5 数据权限涉及的业务模块

数据权限控制需要在以下业务模块中接入：

| 模块 | 说明 |
|------|------|
| **用户管理** | 查询用户列表时按组织过滤 |
| **组织管理** | 查询组织树时按权限范围过滤 |
| **角色管理** | （可选）限制角色可分配的数据范围 |
| **业务数据** | 生产工单、质检记录、设备数据等业务表的查询过滤 |

### 9.6 自定义数据权限

当数据范围类型为"自定义"时，角色可指定具体的组织ID列表：

```
Role.dataScopeType = 4
Role.customOrganizationIds = "1,2,3,4,5"  // 逗号分隔的组织ID
```

|--------|---------|------|

- 用户关联组织，角色的数据权限决定用户可见的数据范围

## 12. 业务流程汇总

### 12.1 超级管理员业务流程

```
创建租户 → 分配子系统 → 创建租户管理员用户 → 绑定租户管理员角色
```

```
用户登录 → 获取用户角色（当前采用单角色） → 获取角色菜单权限 → 获取角色数据权限 → 渲染菜单 → 控制数据访问
```

## 13. 用户编辑角色/租户下拉框逻辑流程

### 13.1 核心规则

**角色下拉框统一只显示当前登录用户所属租户的角色**（包括超级管理员）

### 13.2 角色下拉框显示逻辑 (filteredRoles)

| 登录账号角色 | 角色下拉框显示内容 |
|-------------|------------------|
| 超级管理员 | 只显示当前登录账号所属租户的角色 |
| 租户管理员 | 只显示当前登录账号所属租户的角色 |
| 普通角色 | 只显示当前登录账号所属租户的角色 |

### 13.3 租户下拉框显示逻辑 (showTenantSelect)

**规则：仅超级管理员登录时考虑租户下拉框显示/隐藏**

| 登录账号 | 选中角色 | 租户下拉框 |
|---------|---------|-----------|
| 超级管理员 | 超级管理员 | 隐藏 |
| 超级管理员 | 租户管理员 | 显示 |
| 超级管理员 | 普通角色 | 隐藏 |
| 租户管理员 | 任意 | 隐藏 |
| 普通角色 | 任意 | 隐藏 |

### 13.4 角色下拉框禁用逻辑 (isRoleSelectDisabled)

**规则：仅非超级管理员账号在编辑模式下，需要防止将租户管理员降权**

| 登录账号 | 新增模式 | 编辑模式 - 选中普通角色 | 编辑模式 - 选中租户管理员 |
|---------|---------|----------------------|------------------------|
| 超级管理员 | 不禁用 | 不禁用 | 不禁用 |
| 租户管理员 | 不禁用 | 不禁用 | **禁用**（防止降权） |
| 普通角色 | 不禁用 | 不禁用 | 不禁用 |

### 13.5 提交数据逻辑 (handleSubmit)

| 登录账号 | 选中角色 | 提交的 tenantId |
|---------|---------|----------------|
| 超级管理员 | 任意 | 选择租户管理员时 = 选中的租户ID；其他 = 当前登录的 tenantId |
| 租户管理员 | 任意 | 当前登录的 tenantId |
| 普通角色 | 任意 | 当前登录的 tenantId |

### 13.6 完整流程图

```
┌─────────────────────────────────────────────────────────────────────┐
│                  用户编辑角色/租户下拉框逻辑流程                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  【统一规则】                                                         │
│  角色下拉框仅显示当前登录用户所属租户的角色（包括超级管理员）          │
│                                                                     │
│  【角色下拉框 - filteredRoles】                                      │
│  超级管理员/租户管理员/普通角色 → 统一按 tenantId 过滤                │
│                                                                     │
│  【租户下拉框 - showTenantSelect】                                   │
│  ├─ 非超级管理员登录 → 隐藏                                          │
│  └─ 超级管理员登录：                                                 │
│      ├─ 选中「租户管理员」角色 → 显示                                 │
│      └─ 选中其他角色 → 隐藏                                          │

│  ├─ 超级管理员登录 → 不禁用                                          │

│                                                                     │
│  【提交数据 - handleSubmit】                                         │
│  ├─ 超级管理员 + 选中租户管理员 → tenantId = 选中的租户ID             │
│  ├─ 超级管理员 + 选中其他角色 → tenantId = 当前登录的 tenantId        │
│  └─ 非超级管理员 → tenantId = 当前登录的 tenantId                    │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```
